# 方法来源与贡献边界

## 研究问题的依据

[Konstantinidis, 2026, Discover Artificial Intelligence](https://link.springer.com/article/10.1007/s44163-026-02245-5)，2026-10-24 发表，DOI `10.1007/s44163-026-02245-5`。论文讨论把有关联的报道当作独立佐证造成的过度自信，提出来源依赖图、有效独立证据估计和置信度更新机制。

它是本项目问题定位的相关文献，**没有测试 DSH，也不能替代本项目的效果实验**。其 500 条 FEVER 声明案例按同一 Wikipedia 页面构造来源依赖代理，不是具有完整人工标注传播网络的真实转载数据集。论文中的置信度变化也不能直接当作本插件的错误率改善。

本次是补充相关文献对照。现有 v0.1.0 实现先前采用的是下述标准与常规算法，不能倒写成“原来已复现这篇论文”。插件没有实现论文的分级依赖权重 EIE 或 CONFPROP 置信度公式，未做概率校准。

## 实际使用的方法

| 方法 | 来源及当前实现 |
|---|---|
| 材料、处理过程和引用关系的可追溯记录 | [W3C PROV-O](https://www.w3.org/TR/prov-o/) / [PROV-JSON](https://www.w3.org/Submission/prov-json/)；导出可由 [trungdong/prov](https://github.com/trungdong/prov) 读取 |
| 同一正文指纹 | SHA-256 内容指纹；只用于精确匹配，不推断语义一致、转载关系或独立性 |
| 源头追溯 | 对记录的 derivation 边做图遍历；多父项取源头集合的并集；citation 不合并来源 |
| 保守折叠 | 正文、标题、日期、议题、立场和记录源头均一致才折叠；保留别名、原文和可恢复导出 |
| Agent 工作流 | DSH 正式工具、当前 web service、宿主 Session/调用身份、Native 与 PTC 双执行路径；SQLite 持久化与重试键 |

来源家族数的含义严格限定为“按当前记录关系可追到多少个源头”。两个根可能共享底层观测，错误的 derivation 声明也会导致错误归并；因此 `independence` 保持 `unknown`。这不是论文 EIE 的实现，不是独立验证次数，也不是置信度百分比。

## 如何利用 DSH

- 复用 DSH 的 `ctx.web.search`，无需为相同搜索服务重复配置登录；在结果进入多轮上下文前分配材料 ID。
- 通过正式工具读取宿主 Session 与调用 ID；Agent 汇报引用已存在材料，不能由汇报正文自称宿主身份。
- Native 适合直接查看材料；PTC 可在程序内取得工具的结构化结果，只把所需追溯结果送入模型上下文。这一能力也属于原始 DSH，必须作为强基线比较。
- 案例与引用图保存在模型上下文之外，可按 ID 恢复、撤销链接并重新计算、完整导出；无需每轮让模型重建一套临时状态。

DSH 自身已有超长结果保留和 spill 文件恢复机制。本次实验初版禁用文件工具却一次送入超长材料，造成了不公平的传输条件；修正记录在 [来源追溯试验](ORIGIN-EXPERIMENT.md)。不能把该实验接口错误写成 DSH 的能力缺陷。

## 可以声称什么

工程贡献是把来源关系、恢复、校验与上下文呈现固化为 DSH 可复用工具。来源图、哈希和图遍历都是成熟方法；原始 DSH 也能写代码完成它们。是否减少错误或开销，必须引用具体设置下的配对结果；不把“实现了一个确定性工具”自动等同于“Agent 正确率提高”。

目前实验见 [冲突识别对照](CONFLICT-EXPERIMENT.md) 和 [来源追溯对照](ORIGIN-EXPERIMENT.md)。前者未观察到新增冲突识别能力；后者按 Native 与 PTC 分别报告，不合并选择更好看的结果。
