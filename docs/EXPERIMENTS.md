# 验证报告：有效范围与未证实的收益

运行日期：2026-11-12。代码、输入、协议、实际结果均在仓库中；未将模拟材料写成自然采集数据，也未把计数脚本冒充 Agent 对照。

## 1. 工程验证

- **21 项 Node 测试通过**：同文异源保留、同源不同正文保留、反对意见/标题/日期保护、跨案例引用拒绝、循环拒绝、字面引用检查、关系撤销、历史回执、原子回滚、分页、导出篡改检查。
- 独立 Node 进程可以恢复相同 Session 的案例；4 个进程并发提交 40 条观察，记录与 41 个修订完整保留。该测试发现并修复默认重试键缺少 Session 命名空间的问题。
- 实际 DSH commit `8bd073392eef6f54e921a093b95076248eb08cbb`：10 个正式工具，9 次工作流内嵌调用加 1 次恢复调用；实际 PTC 和 `workspace-write` 子进程沙箱执行通过。重复搜索不重复输出原正文；同键重试不再次调用搜索供应商；卸载重装后恢复。
- 搜索供应商在上述集成测试中是确定性夹具，**没有联网检索、模型或子 Agent 模型调用**。汇报协议经真实工具执行；不能据此宣称已测试所有子 Agent 后端。
- 导出经过 Python **prov 2.1.1** 解析和往返一致性验证。这验证 PROV-JSON 兼容性，不证明关系为真。

首次在外层受限 Windows 令牌下跑 PTC 时，DSH 的 `CreateRestrictedToken` 返回 Win32 87。之后在正常宿主用户令牌中重跑，仍保留 DSH 自身的 `workspace-write` 策略，没有关闭其沙箱。

对应文件：`tests/store.test.mjs`、`scripts/dsh-check.mjs`、`docs/results/dsh-host.json`、`docs/results/prov-interop.json`。

## 2. 真实案例与控制实验

一组 [NASA／能源部 PDF／NOAA 案例](REAL-CASE.md)，两组对抗样例，以及种子 7、11、19 的三组长文转述链。另加三组故意写错来源边的敏感性实验，共 9 个案例。

比较原材料计数、只按正文精确去重、来源图视图。**前两项是确定性表示/计数基线，不是原始 DSH 模型的回答。** 三组都可以看到输入中的引用关系；插件没有凭空推断 oracle。

| 检查 | 结果 |
|---|---|
| 正确给定来源关系的 6 个案例 | 插件来源家族计数均符合夹具，需保留内容损失为 0 |
| 同文字、不同来源对抗例 | 普通正文去重丢掉一个来源；插件保留两个并标记关系未知 |
| 混合报道、相反发现 | 新试验与反对意见保留；citation 不合并来源 |
| 故意错误的 3 条 derivation 输入 | 插件都把实际两个家族误算为一个；正文仍保留。这是明确失败边界 |

NASA 小案例：6 条材料折叠为 4 条正文，计作 2 个来源家族，独立性仍为未知。字节开销为原始 1,889、普通去重 1,444、插件 2,742。**短材料增加来源元数据后更长。**

长文转述案例 seed=7：原始 26,472 字节，普通去重 5,417 字节，插件 6,744 字节；插件较原材料少约 74.5%，但比普通去重更大。它保留的是来源和安全边界，不是最激进的压缩率。这里测量的是 **UTF-8 字节，不是 token**。

`count_based_false_consensus` 是人为的“候选来源数 ≥3”阈值诊断，**不是测得的大模型错误结论率**。它不能用来声称插件降低了真实世界幻觉率。

对应文件：`examples/cases.json`、`scripts/benchmark.mjs`、`docs/results/benchmark.json`。

## 3. 真实 DSH 模型小试验

在实际 DSH headless 中使用 `deepseek-official/deepseek-flash`、reasoning effort `low`。三组各一次、各回答相同的三个案例；禁用工具，直接给固定材料或插件生成的视图。这是**固定上下文阅读对照**，不包括自主检索和多 Agent 调度。

统一每组输出预算 8,192 token。输入含同样的业务任务和来源断言；普通去重组只保留首次出现的正文条目，因此同文异源条目的来源信息会损失。更完善的普通脚本也可保留来源别名，本实验未证明优于这种脚本。

| 组 | 完成情况 | 来源计数核查 | 使用量：输入含缓存／输出／总计 |
|---|---|---|---|
| 原始材料 | 推理达到输出上限，没有最终答案 | 不可评分，不能算作错误答案 | 1,453 / 8,192 / 9,645 |
| 普通正文去重 | 完成 3 题 | 2/3 正确；同文异源误计为 1 | 1,232 / 916 / 2,148 |
| 插件视图 | 完成 3 题 | 3/3 正确 | 2,612 / 1,481 / 4,093 |

两个完成组都没有声称已建立三次独立确认，因此**未观察到插件降低错误结论率的证据**。插件组比普通去重组用了更多 token。一次运行无法估计稳定的完成率、错误率或成本收益。

还保留了 [首次尝试](results/pilot-initial-attempt.json)：它使用 4,096 输出预算，工具限制插件因作用域配置错误没有加载，但实际三组均未调用工具；原始组当时完成三题，普通去重组达到上限。修正限制配置后三组全部重新跑，未挑选对插件有利的单次结果拼成一张表。**原始 DSH 有能力正确处理这些来源关系。**

对应文件：`scripts/agent-pilot.mjs`、`docs/results/agent-pilot.json`、`docs/results/pilot/*-input.json`、`*-final.json`。原始事件日志留在本地 `.verification` 指向的临时目录；公开的只有夹具、最终回答、使用量和结果，不含模型登录信息。

## 4. 当前能支持的结论

该插件能把明确来源引用、保守重复折叠、可恢复记录和导出追踪固化为可复用流程。给定正确来源关系时，它能防止简单文本去重损失同文异源材料，也能避免把已记录的转述节点额外算作源头。

尚不能支持：自动发现所有转载、识别恶意伪造出处、保证摘要忠实、证明统计独立、普遍降低错误结论率、普遍节省 token、优于认真实现来源管理的普通脚本。更大规模盲测和真实自主 Agent 工作流仍是后续验证工作。

## 5. 后续冲突识别验证

2026-11-12 对现有 v0.1.0 另做了运行前冻结协议的实际 DSH 工具对照：12 个案例，原始材料、保留来源的普通去重、插件视图，三次顺序重复和一次 low 推理补充。三组均识别全部冲突，无误报；配对增益为 0。当前没有证据支持“插件发现原始 DSH 识别不了的冲突”。详见 [冲突实验报告](CONFLICT-EXPERIMENT.md)。此实验没有修改插件运行代码，也没有替换或隐藏本页早期小试验的结果。
